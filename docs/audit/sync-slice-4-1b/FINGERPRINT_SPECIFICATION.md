# Deterministic Table Fingerprint Specification (Slice 4.1B)

## 1. Objective
To provide strong deterministic integrity evidence that the serialized business-column state matched before and after the rollout during the Phase 4 Slice 4.1B production rollout on Azure SQL databases `IProgramDb2026` and `IProgramDb2027`, where only the newly populated `SyncId` column was altered.

---

## 2. Algorithm & Methodology

The table fingerprint is calculated natively inside the SQL Server engine using deterministic XML serialization and the SHA2_256 cryptographic hashing function.

### SQL Query Specification:
```sql
SELECT COALESCE(
    CONVERT(VARCHAR(64), HASHBYTES('SHA2_256', 
        (SELECT [Col1], [Col2], ..., [ColN]
         FROM [dbo].[<TableName>]
         ORDER BY [<PrimaryKeyColumn>]
         FOR XML RAW, BINARY BASE64)
    ), 2),
    'EMPTY_TABLE'
) AS TableHash;
```

### Key Properties:
1. **Dynamic Column Discovery with Strict SyncId Exclusion:**
   - Columns are discovered dynamically from `sys.columns` ordered by `column_id`.
   - The `SyncId` column is explicitly filtered out (`c.name != 'SyncId'`).
   - All original domain business columns, audit fields, flags, and foreign keys are included.
2. **Deterministic Row Ordering:**
   - Rows are ordered by Primary Key (`ORDER BY [<PK>]`), ensuring that physical storage layout, page reorganization, or index rebuilds do not change the serialized byte stream.
3. **Engine-Side Native Execution:**
   - Entire calculation executes within SQL Server RAM/CPU without network serialization, transferring only a single 64-character hex string to the client.
4. **Execution Performance:**
   - ~500ms to 1,500ms for standard tables (1k–15k rows).
   - ~4.4s for large tables (`FormDetails` with ~30k–55k rows).
